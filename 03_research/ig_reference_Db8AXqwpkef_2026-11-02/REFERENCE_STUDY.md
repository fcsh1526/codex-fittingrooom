# 「街角赴約」參考片：OpenMontage 實際拆解

日期：2026-11-02。來源：https://www.instagram.com/mika.dono3/reel/Db8AXqwpkef/ 。帳號 mika.dono3，貼文「抱歉我化妝晚了，等很久了嗎？」。這是研究素材，非 Mira 製作素材或身份參考。

目的：回答新工具能否幫 Mira 學習他人影片的表演與拍攝細節。本次僅讀取、下載研究、抽格及企劃，不生成新影像、不改已核准影片、不付費、不採用完整製作管線。

## 使用者修正：先察看來車再過街

2026-11-02 使用者指出：2–3 秒的側看是過馬路前察看有無來車。初版雖記錄側看與回正，卻把原因泛化成生活感／赴約表演，漏掉道路、注意目標與跨出路緣的因果關係；不能沿用為任意側看鏡頭的指令。以下以這項修正為當前解讀，保留原始工具 JSON 不修改。

證據責任：抽格由助理設定取樣方式、OpenMontage 執行；動作與情境意義由助理判讀。原始工具的 content_analysis.summary 與逐格 description 為空字串，沒有獨立辨識「看車」或「赴約」。使用者對動作原因的修正屬明確提供的參考解讀；不能倒寫成工具已自動辨識成功。這一例也不支持聲稱已有量化的語意判讀準確率。

## 已實際完成

- 補齊 OpenMontage 專用 venv 的免費依賴 yt-dlp 2026.10.26，未升級其餘套件。瀏覽器可看原片，但 blob 下載及 pageAssets 匯出失敗；最後透過 yt-dlp 取得公開影片。下載使用 Windows 系統受信任憑證，未停用憑證驗證、未匯出登入 cookies。
- 檔案 reference.mp4：720×1280，30fps，216 個影格；影像流長 7.200 秒，音訊／容器長 7.334649 秒。瀏覽器播放的另一個版本回報 7.219953 秒，分析時間表以本機影像流為準，不混用容器長度與有效影像範圍。
- 執行 tools/analysis/video_analyzer.py（deep）：產生 metadata、單一 scene 區間、四張 keyframes、audio_energy。完整原始結果保留在 analysis_verified/video_analysis_brief.json。
- 使用 tools/analysis/frame_sampler.py 的 timestamps 策略，取 0、0.5…7.0 及 7.1 秒，共 16 格，輸出 sampling.json 及 reference_contact_sheet.jpg。四節點摘要另存 reference_four_beats.jpg。
- 已逐張觀察這 16 格；這是有時間標籤的視覺分析，不能記為完整原速動態 QA、步態通過或生成重現成功。

## 工具結果的限制

- 第一次受限環境解碼失敗仍回傳 success=True，且給出錯誤的 animated-explainer／motion_required=false 預設建議；保留 analysis/video_analysis_brief.json 作為失敗紀錄，不採其結論。一般本機執行才完成有效抽格。
- 成功執行的版本也將 motion_type 記為 unknown、flow_variance=-1，不能宣稱本輪已量測光流、路線、步速或自動辨認表情。
- cuts_per_minute=8.18 是程式拿「scene 數」除時間；單一區間沒有內部切點，不能解釋為本片每分鐘剪八次。pacing_style=steady_educational 亦不是可靠的內容分類。
- 語意、眼神、微笑與畫面尺度由助理觀察補充。畫面變化不能證明拍攝器材、焦段、生成服務或真實拍攝參數。帳號標示 AI 不等於能識別模型。
- 這次是把參考轉為可重用的導演筆記，沒有訓練生成模型，也沒有把影片動作自動轉成 Grok 可精準重播的控制訊號。

## 五面向拆解（人工判讀）

**Subject／人物**：一位主要人物，深色貼身上衣、短裙、絲襪與短靴，一手提小包，另一手臂搭外套。背景行人另列為環境人物，不作身份連續性要求。Mira 應沿用自己的模特兒及服裝。

**Subject Motion／人物動作**：持續由街角走近。約 2–2.5 秒側看，約 3 秒轉回前方；依使用者修正，此段是察看來車、準備過街，不能解讀為對鏡頭擺姿或任意回望。約 4 秒另有短暫側向視線，其原因未確認；約 4.5–5.5 秒笑容明顯，6–6.5 秒低眼，7–7.1 秒再看向鏡頭。頭髮、提包、外套與步伐有連動。這些是取樣時間的狀態，眼神切換、腳步跨越路緣的精確先後仍需更密集抽格；不新增原片未見的等車、煞車或揮手情節。

**Scene／場景**：日間街角，石牆、轉角路緣、停車、腳踏車、背景行人。遠景到近景保持同一空間的連續感。影片內取樣未見額外字幕／圖形；IG 頁面文案與介面不屬於原片的字幕層。赴約動機由文案與表演共同支持，是解讀，不是檔案 metadata。

**Spatial Framing／構圖**：開頭人物已存在於街角遠處；早段完整身形、留有較多街景，接近後變成以人物為主的全身構圖，再逐步裁到腿部與上半身，結尾靠近臉部。不是人物只在同一尺寸的遠景裡走動。初段畫面偏糊、之後變清楚；不能單憑成片判定是對焦、生成或壓縮因素，不必當作 Mira 必學效果。

**Camera／鏡頭**：視角高度大致接近日常人像觀看，未見必須重現的複雜環繞軌道。末段背景石牆／停車／右側建物位置有變化，視覺上有輕微重構圖，不能先鎖定為完全固定鏡頭；精確平移、轉向、變焦的成分尚未量測。實際焦段與拍攝速度未知，不宣稱為某鏡頭或慢動作。

## 時間表與值得學的作用

| 取樣區間 | 看見什麼 | 對 Mira 的意義 |
|---|---|---|
| 0–1.5 秒 | 街角已有完整人物，持續接近，環境建立距離 | 用出現位置與空間建立期待，不以空景長等候 |
| 2–3 秒 | 側看後回到前方；使用者指出是察看來車、準備過街 | 把路緣／車道位置、視線目標與過街先後連起來，不能抽離場景改成任意側看 |
| 4.5–5.5 秒 | 人物明顯變大，笑容加深，衣服仍可辨讀 | 構圖和情緒一起推進，服裝資訊隨接近自然出現 |
| 6–7.1 秒 | 低眼後再看鏡頭，結尾親近 | 留一個眼神回應作收尾；避免一直傻笑或過近造成比例失真 |

修正後解讀：整體赴約關係由貼文文案與後段互動支持；中段先有「為過街而察看車流」的環境行動，之後才接上走近與微笑。不能讓整體赴約主題取代每個動作自己的原因。初版「側看是生活中的注意力變化」過於籠統，不能作生成執行依據。

## 轉成 Mira 的最小測試提案（未生成、未核准新製作）

只做一位模特兒、一套服裝、單一連續鏡頭，約 7–8 秒。先做有時間標籤的起點／中段／結尾構圖與表演節點；根據 Mira 素材是否支援接近路線與近景比例，再列缺圖，不能直接把遠景照片硬推成極近臉。

修正後必要節點：街角可辨讀的出現 → 在過街位置察看車流並接續過街 → 走近時笑容展開 → 輕微低眼後抬眼回應。先確認 Mira 起始圖的路緣、車道與走向能支持這個行為，方向以實際場景為準，不能隨意補斑馬線或車輛。步伐輕快、手提物有受力連動，不額外疊大幅轉肩與抬手，以免重演 M01 漂移。鏡頭方案須另比較原片與固定鏡頭簡化版，不能誤稱兩者完全相同。

成功判準：不看說明也能感覺人物在與鏡頭前的人赴約；能指認四節點而非一個笑容維持到底；接近尺度連續、臉與身體比例合理；腳掌接地、手與物件連動、身份服裝穩定；開頭及中段讀得到服裝；最後仍依 Mira 原速全片 QA 與使用者核准分開記錄。抽格可準備這個測試，無法保證生成通過。

## 動作描述與情境說明：待驗證的提示策略

動作描述提供可見的方向、先後與程度；情境說明提供動作的對象、理由及場景關係。兩者不是對等替換：單寫側看無法指定是察看車流，單寫確認安全過街也無法確保模型採用我們想要的視線、步伐與時機。先採「簡短可見情境＋必要的可見動作順序」作測試假說，不能稱已證實對 Grok 較好。

若測試措辭差異，固定起始圖、模特兒、服裝、鏡頭、片長、生成服務與可取得的設定。A 保留具體動作；B 在同一份動作敘述前只增加察看來車的簡短情境，避免同時更改動作與場景。若服務可固定 seed 則固定並記錄，若無則明示隨機性。觀察視線目標、路緣前後時序、步伐、情緒是否符合，及是否多出車輛、停等或鏡頭變化。單次不同輸出僅作探索，不能證明是措辭造成，也不能估計穩定成功率；不為比較而立即消耗額度。

外部依據：Runway 的官方 Gen-4 提示指南建議具體可見動作、簡潔敘述與一次改一項元素（https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide）。這是其他模型的官方建議，不是 Grok 的對照實驗結果。《Motion Prompting: Controlling Video Generation with Motion Trajectories》（CVPR 2025，https://arxiv.org/abs/2412.02700）指出純文字對細微動作與時間安排的控制仍有限；不能由此推論當前 Grok 的個別成功率。
