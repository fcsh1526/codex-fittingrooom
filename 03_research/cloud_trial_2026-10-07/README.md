# M02 雲端試作包

目的：驗證「讀取素材 → Grok 新來源 → 剪輯 → 審看 → Drive 另存」能否完全在雲端完成。這是隔離的單支測試，不是整個工作流已搬移。

## 目前已有與缺少

- M02 v3 face/full 身分參照。
- 第一套近起點 v2、第二套匹配起點 v3，皆有逐張核准與精確檔案雜湊。
- 兩套各一張全身、一張搭配重點圖：四個可用畫面已核准，不要求硬剪四段。
- 第一套退遠原片：720×1280、24fps、145幀。抽樣檢查與獨立紀錄已保存；完整成片核准不因此通過。
- 第二套匹配起點的新影片尚未生成；outputs/source_B.mp4 不存在是正常狀態。
- 雲端瀏覽器、Grok 操作、雲端剪輯及存檔尚未實測。

## 最短執行順序

1. 在真正雲端工作中取得 ZIP，安全解壓並讀 AGENTS.md。確認沒有呼叫本機橋接；以 inputs_manifest.json 驗證所有輸入。
2. 確認雲端 Python 與依賴可用，再執行 `python tools/cloud_video.py preflight`。這只解碼既有 A 並做一秒編碼測試，不是可發布 Reel。沒有執行工具就記錄限制，不要求使用者安裝本機軟體。
3. 用雲端瀏覽器登入 Grok，實際確認保存的 `Mira M02 v3`。如果保存的參照不可用，依介面支援方式使用 inputs/M02_face.png 與 M02_full.png，記錄實際方式；名稱本身不會提供身分資訊。
4. 將 inputs/B_matched_start_v3.png 指定為 First frame，同時保持人物參照；無 Middle/Last frame。實際確認6秒、720p、9:16、音訊關閉，再送 prompts/B_approach.txt。第一候選最多重試一次。保留設定、時間、提示詞、結果網址及下載收據。
5. 將新 B 放入 outputs/source_B.mp4，完整解碼，檢查開頭、四分之一、中段、四分之三、結尾和步伐瞬間，並完整播放。人物、灰肩帶、無鞋帶便鞋及背景固定物不可跳变。未通過不剪正式候選。
6. 寫 outputs/source_B_QA.json，包含 source_sha256、approved_sampled_dynamic_qa、實際抽查方法、完整播放狀態、缺陷、重試次數、主動與等待時間。只有實際抽查通過才填 true；不能複製 A 的評語給 B。
7. `python tools/cloud_video.py compose --b-sha ACTUAL_NEW_B_SHA`：預設 A[0,96)、B[0,144)，18幀0.75秒交疊，約9.25秒。這是初始候選，需要重查實際18對轉場幀、頭腰鞋與背景線條。若不合適先重選原生片段，不用改速、柔焦或長淡化掩飾。當前工具只接受同尺寸24fps來源；若實際輸出不同先記錄，不自動拉伸或改速。
8. 完整播放整支乾淨候選，交使用者核准。技術或抽樣通過與使用者核准分開記錄。另存到本試作 Drive 資料夾並讀回核對；保留第一波五支。

## 雲端通過條件

上述讀檔、瀏覽器、取片、剪輯、QA與Drive存檔皆在雲端完成，沒有本機檔案/工具/瀏覽器呼叫，才能記為「單支雲端路徑通過」。素材準備、文件上传或本機 preflight 通過都不算。人為登入與手機/網頁視覺審看可以保留。

既有圖重用的成功不證明雲端能生成新起始圖；要稱完整每週產線可搬，仍需另外驗證內建影像工具使用 face/full 參照、交付新圖、核准後動畫的能力。單支通過也不證明每週成功率或曝光。

## 環境

Python3.11+、Pillow、NumPy、imageio-ffmpeg（及其執行平台的FFmpeg）。依賴需求在 tools/requirements.txt；不要搬 Windows 二進位套件。原始紀錄保留舊 Windows 路徑作來源證明，以 manifest 的封包相對路徑取檔。

本包不含登入資料、不含第一波五支媒體，也不包含已拒收的接段v1或舊B1來源。evidence/protected_originals.json只保留本機驗證紀錄；雲端不能宣稱已重新驗證未帶入的原始檔。
