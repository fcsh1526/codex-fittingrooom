# W47 M01 漏斗領｜兩種導演流程空跑

2026-11-20。題目是「同一件石灰色短外套敞開和立起時，臉旁的輪廓有什麼差別？」基準採用 W47 M01 實際走過的導演與剪輯流程，另對照 11/20 更新後的 Mira 工作表。兩邊共用 M01、同一套衣服、同一批既有影片、原速、無音無字、9:16。剪輯同為 24 fps、112 格，以便把注意力放在鏡頭的順序和作用。IG 參考只供分析。

逐鏡原片畫格對照（本機素材 `storyboard-comparison.jpg`） · Mira v3 原剪（本機素材 `../../runs/2026-W47/reels/M01/full_edit_v3/M01_W47_v3.mp4`） · [OpenMontage 原生專案識別](cinematic-paper/project.json)

## 從同一個題目得到的兩種剪法

| 決策 | Mira 實際 v3 | OpenMontage cinematic 紙上方案 B |
|---|---|---|
| 第一次吸引注意 | 半身、手在領口，先讀人物反應。 | 開領、閉領同時入畫，先給觀眾選擇。 |
| 下一拍為何繼續看 | 期待她會怎麼回應。切全身，笑著招手，雙鞋與整套比例入畫。 | 期待看清兩者的感覺。畫面回到風吹開領的瞬間，一次側傾呈現領緣、內搭與肩線。 |
| 運鏡與空間 | 半身切全身，再進並排。v3 在全身已成立處切入，避開前版拉遠；取用雙腳站定段。 | 並排切回單人中景，再切同級閉領中景。鏡頭沿用原素材，靠人物的動靜和版面轉換引導注意。無須設計往玻璃方向的步伐。 |
| 留給觀眾的最後一眼 | 1.75 秒並排，可回頭比對領形。 | 2 秒留給閉領、下顎和視線。觀眾需記住開頭的開領輪廓。 |
| 代價與看片問題 | 人物可親，服裝全貌清楚；招手可能蓋過衣領。看到招手時，眼睛還在找領口嗎？ | 構圖集中，缺全身展示；第一秒要辨認兩個相近的領形。觀眾在切回單人前看懂選擇了嗎？ |

**既有新版 Mira 的位置。** 11/20 的 Mira 四格預演已經移除招手，改成開領、迎風、閉領、並排。它和方案 B 都能在現有素材中解決缺少扣合動作的問題。兩者真正值得比較的是「並排放在最後，讓人核對答案」，還是「並排放在最前面，先讓人有個問題」。六種方法、固定機位和關鍵格本來就在 Mira 工作流中。[Mira 四格預演與判讀](../2026-11-20_directing/REVIEW.md)

## Cinematic 的八個階段

| 階段 | 本次輸出／決定 | 和 Mira 導演流程相比 |
|---|---|---|
| Research 研究 | 凍結共同證據：slow.and 的穿法比較、syuan_ord 的視線、W47 扣領退件與 W46 並排接受範圍。 | Mira 的人物、服裝和退件紀錄較細。沿用同一資料集，兩邊都沒有新增外部搜尋。 |
| Proposal 提案 | A「到門口遇到風」走生活敘事；B「同一張臉，兩種領線」走選擇與對比；C「跟著她的視線」走人物互動。選 B 作比較假設。C 欠缺畫外人物的回應，且領形退為次要。 | W47 原案已比較六種呈現方法。這次再多問一層：即使用同樣的素材與方法，不同順序讓觀眾期待什麼？ |
| Script 劇本 | 先看見兩種領形 → 風吹起來 → 回到安定的閉領。每一拍都能指回一段現有畫面。 | Mira 原案的「遇冷扣領」有動作因果；選段後扣合缺失。兩條流程都需要改寫觀眾期待。 |
| Scene plan 分鏡 | 三拍分別負責提問、反應、收束。鏡頭維持同側光線與門邊地標；第二、三拍的手位改變是狀態切換。 | Mira 對手物接觸、衣領遮擋、玻璃邊界和身份檢查較具體，這些規則隨片沿用。 |
| Assets 素材 | 登錄三段本機動態並依雜湊核對；已算入 v3 的並排直接複用。四個共同候選影片均已完整解碼。 | 此案的缺口是扣合過程。A、B 都可用現有畫面說明開閉兩態，只有想教如何拉上才需要可信的操作鏡頭。 |
| Edit 剪輯 | 方案 B 的三段格數為 24、40、48。以原片格號驗接點與片長。 | Mira 的 v3 分別為 34、36、42 格。人物、全身、並排和比較、反應、靜下來是兩種不同的敘事。 |
| Compose 合成 | 紙上核對三段合計 112 格、維持 9:16 與原速、全段靜音、無疊字。取樣並排已預合成，後續如試剪只需原速硬切。 | 上游預設也會討論音樂、色調和合成器。本輪固定相同規格，保留畫面順序這個主要變因。 |
| Publish 交付 | 列出未驗項目：首秒能否讀懂、切點是否突兀、閉領停留是否太長。無新成片、封面、上傳或發布。 | Mira v3 有實際成片，仍待整片回饋；B 只有紙上剪輯。觀眾成效兩者皆無從判定。 |

## 方案 B 的紙上剪輯表

格號為起含迄不含，每個來源均為 720×1280、24 fps。並排第一拍取自既有 v3 的並排段。

| 成片格 | 來源格 | 切點的導演理由 |
|---|---|---|
| [0,24) | v3 [70,94) | 第一眼同時看見兩種領形；用同一張臉和背景提示這是比較。 |
| [24,64) | wind [12,52) | 切回左側人物的開領；從迎風動作起勢看到重心改變，沒有數位推近。 |
| [64,112) | closed [16,64) | 讓移動的肩線切到穩定的閉領；手和臉的位置會跳，需在原速試剪檢查。 |

圖中上排取 v3 第 18、54、95 格，下排依序取 v3 第 83 格、wind 第 28 格、closed 第 32 格。這些是代表格，不能據此判定整段動作流暢。

## 實際執行範圍

本機 OpenMontage 版本為 `08e2151`。實際執行原生專案初始化、cinematic manifest 載入、工具登錄探索、六份草稿的原生 JSON Schema 驗證、來源雜湊及剪輯格數核對。Remotion 附帶的 ffprobe 在本次讀片時異常退出，媒體規格與格數改用本機 FFmpeg 完整解碼核實。所有選段都在原片範圍內，累計覆蓋 112 格。

空跑採固定參考庫。原生正式研究規格要求至少八次網搜；研究 checkpoint 因此記為 in_progress。三個方向的選擇是這次比較用的編輯假設；後續階段在 dry_run 存放草稿，沒有寫入人為核准、生成任務或成片完成狀態。此次 Grok 與其他生成服務調用次數均為 0，沒有渲染新影片。
