# Mira Reel 製作系統 v1

建立：2026-10-27。這是跨系列的製作規格與技能入口，不是新一週企劃、已完成的新預演器或新影片。

## 從觀看目的到可拍攝的設計

流程為：**觀眾收穫 → 服裝關係與系列 → 呈現方法 → 線稿分鏡 → 必要的空間／雙路徑預演 → 素材需求 → 生成與剪輯 → 整片驗收 → 發布成效。**

每份製作案保留以下六份相互連結的交付物；短片可以合在少量檔案內，不必為每一項另建資料夾。

| 交付物 | 實際用途 | 完成判斷 |
| --- | --- | --- |
| 影片企劃 | 一句話說觀眾要看什麼，服裝如何支持它 | 例如「挑選五天通勤靈感」，並指出每套可見差別；不能只寫精緻、有節奏 |
| 製作計畫 | 記來源、衣服、方法、時間、場景、鏡頭與依賴 | 分鏡、預演及素材清單引用同一版本；格式見 plan-contract.md |
| 線稿分鏡表 | 一眼看到開頭、發展、結尾與衣服閱讀順序 | 每鏡有首尾構圖、人物／鏡頭箭頭、時間、看點及接點；必要才加中途格 |
| 空間預演 | 對連續行進／繞拍，驗證路線如何變成畫面 | 同一時間可對照俯視雙路徑與9:16相機視角；其他方法可註明不適用 |
| 逐鏡製作卡 | 告訴操作者最少需要什麼圖、如何生成及取段 | 首／中／尾的用途、參照角色、實際可用控制及驗收問題都有依據 |
| 驗收與交付紀錄 | 分清技術完成、視覺接受與實際發布 | 精確檔案、來源區間、尚存問題、核准範圍、交付與成效各自可追溯 |

此版附可重用計畫模板與結構檢查腳本。它檢查資料、時間與依賴，不替代相機視角渲染，也不把AI生成轉成可精密控制的實景攝影系統。現有通勤研究的繪圖／預演程式可作實作來源，但其中舊版幾何錯誤或與成片不一致之處不能直接升格為通用引擎。

## 線稿應能回答的問題

- 開頭第一個完整畫面讓人看什麼？結尾停在哪個服裝資訊？
- 人物由哪裡走到哪裡，如何擺姿勢；鏡頭的起點、終點、朝向如何變？
- 衣服真正清楚、完整且未受轉場影響的時間有多少？遮牆、混衣與僅見臉的時間不能算完整讀衣。
- 下一鏡接入時，人像尺度、頭肩／腰／鞋落點、行進方向、步相、亮度及背景線條是否相容？
- 每一個推近、轉側、場景改變有增加服裝資訊嗎？只為變化而變化的鏡頭應刪減。

「節奏明快」需拆成可比較的目標：多久出現新的服裝資訊、動作有沒有停住、畫面如何推進、各套清楚閱讀時間、接點是否打斷動勢。不要用加快人物或縮短所有鏡頭替代整體編排。

## 計畫與實際分開

同一份計畫以整片畫格時間為主；來源影片各自的零起算時間保存在剪輯表。線稿、俯視圖、相機預演和素材卡帶同一計畫版本／雜湊。修改路線或時間後，標記哪些派生圖與接點需重算。

生成後逐鏡記錄：原片實際時長／尺寸、可用區間、原速步態、衣服可讀性、場景差異與控制是否達成。將它與計畫比較，不能為了讓記錄看起來一致而倒改原先計畫。

## 審閱節點

先交一份能看懂的企劃＋線稿；連續路線片同時提供俯視及相機視角。企劃含實質新方向時由使用者選定，已核准設計的常規整理直接完成。新AI照片仍按現行規則逐張視覺核准，之後再生成動態。單鏡通過後驗相鄰接點，最後看整片的資訊與舒服度。

不要把每項檔案整理變成一次確認。也不能把先前的「這一鏡可用」擴成「全片可發布」。抽幀、程式檢查、正常播放和使用者核准要記實際範圍。

## 方法庫如何成長

先依觀看目的查閱 `09_sops/mira_reel_method_catalog.md`；可沿用、組合或提出庫外方法。研究與製作依 research-and-production.md 並行。完成一次影片後，補進該方法的可用條件、失敗條件和實際成本。一次接受記為範例接受；不同服裝／人物再次成立才有重複性證據；發布數據才回答觀眾是否喜歡。

若只是換衣服、動作、推拉鏡或鏡頭排序，歸在同一方法的變體。只有觀眾的觀看順序或影片敘事機制改變，才考慮新增製作方法。
