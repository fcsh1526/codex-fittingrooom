# 從分鏡到剪輯台

每支片從一個能用畫面回答的穿搭問題開始。把答案落在某個可辨認的瞬間，例如肩膀轉到側面時，原先貼在背景上的褲管外弧才分離出來。沿用既有拍攝卡或[單片工作表](../assets/director-sheet.template.md)，由同一份表追蹤分鏡、選段與粗剪。鏡數、片長和呈現方法依這一片決定。

### 1. 編輯先決定觀眾在等什麼

寫出第一眼看到什麼、哪個未完成的動作或差異讓人想往下看、答案落在哪一格、最後想留下什麼印象。在 9:16 線稿或現有取樣上圈出開場、揭曉、收尾的注意點。三者可以在同一鏡裡。若遮住文案以後連導演也分不清前後差別，先改衣服的可見關係、構圖或事件。

### 2. 把演員與攝影機分開指導

每一拍先交代她此刻要做什麼、注意誰或什麼，以及視線、肩、手、重心如何接續。再選能看清這個反應的機位。寫出起幅、落幅、機位高度與方向、人物和背景各往哪裡動，以及觀眾新看見了什麼。機位固定時，讓手離開領口、身體轉到側光等畫面變化承擔節拍。

例如街頭跟拍要讓觀眾看到包鏈從手臂後露出，先畫起幅的遮擋、人物走向與落幅的可見位置。若只需比較領形，可用定機同尺度硬切。對玻璃、門框、路緣等有動作風險的場景，畫出可行走區、鏡頭所在側與人物停止點。跨鏡行進再用[同一時鐘的俯瞰與相機預演](route-previs.md)檢查步相和背景位移。

### 3. 在生成前剪一次分鏡

把關鍵格依預定秒數播放，先從頭看一次，再回看最難的接點。註明哪一拍是期待、哪一拍發生變化、留了多久讓眼睛讀衣；若拿掉某一鏡，說清會失去什麼。固定圖的定時預演檢查順序與停留，走位或運鏡疑問需用動態線稿或既有原速片段驗。鏡頭能說清楚以後，再盤點可用原片、已核准首圖及真正缺的素材。

可用現有分鏡工具，或以 [animatic.py](../scripts/animatic.py) 將圖片依格數輸出為無聲 9:16 預演。清單提供整片 fps，每一列填相對於清單的 image 路徑與正整數 frames。程式完整保留圖片，比例差異以留邊顯示。下方 W47 實例附可執行清單。

### 4. 帶著實際素材回到剪輯台

逐段按原速找出動作起因、反應最高點、收束和服裝可讀時段，在同一行補來源檔與起含迄不含的格號。以預定揭曉為中心，先檢查前後兩鏡接起來是否成立，再排全片。剪點可落在視線改向、手離開衣服、步相延續或構圖呼應；表情正在發展時，保留反應完成的時間。並排則核對兩側的可讀區間確實重疊。原片長度和音樂節拍只作素材條件；Mira 原速無字母版先能獨立成立。

關鍵動作失敗時，當場寫出兩個判斷：裁掉問題區後，觀眾還看得到原來答應的事嗎？如果只看得到動作前後兩種狀態，這支片是否值得改講「兩種狀態的差別」？裁切仍保有看點就重剪；缺了揭曉則改寫相關分鏡，或定位缺的單一動作與素材。回查原授權範圍與具體退件原因，再決定如何接續。

### 5. 用兩次不同目的的觀看完成審片

第一次按原速、手機直幅、先不看表，寫下「我先注意哪裡、何時開始期待、哪個畫面回答了我」。把失去注意力或來不及讀衣的第一個時間點記下來。第二次回到該處及相鄰鏡頭，檢查身份、手物接觸、腳與障礙物、人物尺度、轉場和讀衣時間。保留最有效的反應，將問題回到對應的分鏡、拍攝或剪點處理。無法連續原速目視時記實際取樣範圍。最後分別記剪輯者觀察、使用者對精確版本的接受，以及發布後才有的觀眾數據。

### 來源與適配

**整支 Reel 交給 OpenMontage 時的入口。** 從本機 `openmontage/AGENT_GUIDE.md`、`PROJECT_CONTEXT.md` 與 `pipeline_defs/cinematic.yaml` 開始。先用工具登錄表查當次可用能力，核對 Mira 的素材、生成途徑與範圍，再用 `lib.checkpoint.init_project` 建立獨立製作案。逐階段讀該案的 director skill，將研究、提案、劇本、分鏡、素材、剪輯、合成與交付記在同一案的 artifacts 和 checkpoints。Mira 的工作表可附在分鏡階段，實際選段回填到 edit_decisions。既有 Grok 網頁生成若被選用，須將取回的原片與來源記入 asset_manifest；網頁登入和 registry 的 API 能力各自核對。交付或外部發布依使用者授權範圍處理。[本機操作指南](../../../openmontage/AGENT_GUIDE.md) · [Cinematic 各階段與輸出](../../../openmontage/pipeline_defs/cinematic.yaml)
